# Venue Management API

An API for organizing venues, their branches, and the resources managed at each branch.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Where things live

- `lib/api-spec/openapi.yaml` — source of truth for the API contract
- `lib/db/src/schema/` — PostgreSQL schema for venues, branches, and resources
- `artifacts/api-server/src/routes/venues.ts` — request validation and creation handlers
- `artifacts/api-server/src/routes/health.ts` — health check endpoint

## Architecture decisions

- Venue hierarchy is represented as `venue -> branch -> resource`, with database foreign keys and cascading deletes.
- IDs are UUIDs generated by PostgreSQL so clients do not need to provide identifiers.
- OpenAPI-generated Zod schemas validate request bodies, path parameters, and response payloads.
- Optional nullable database columns are omitted from JSON responses when they are not set.

## Product

- Create a venue with contact and location details.
- Create branches under an existing venue.
- Create resources under an existing branch, including capacity, active status, and arbitrary metadata.
